# monday.com board setup

Follow this once. Takes about 15 minutes.

---

## Do I need to clean the spreadsheets first?

**No — and you shouldn't.** The agent's cleaning layer is built for exactly the defects
in these files, and the assignment is graded on handling them. Pre-cleaning would delete
the evidence that it works.

Two files have already been prepared for you:

```
d:\skylark drones\monday-import\
    Deals Pipeline.csv     346 rows, 12 columns
    Work Orders.csv        176 rows, 38 columns
```

Generated by `python scripts/make-import-csv.py`. The **only** changes made are the ones
Monday's import wizard needs:

| Change | Why |
|---|---|
| Work Orders: blank first row removed | Row 1 was empty and row 2 was the real header. Monday would treat the blank row as headers, leaving every column unnamed — this breaks column mapping completely |
| Dates written as `YYYY-MM-DD` | Removes any DD/MM vs MM/DD ambiguity in Monday's date parser |
| Currency rounded to 2 decimals | Source has values like `2984097.3600000003`. Total impact across all rows is under one rupee |

**Everything else is preserved on purpose**, including the two repeated header rows in
Deals, the 52% missing deal values, the `BIlled` typo, the four always-empty columns and
the mixed quantity units. The agent detects and reports all of them.

## Step 1 — Import the Deals board

1. In monday.com, click **+ Add** (top left) → **Import data** → **Excel / CSV**.
2. Upload **`Deals Pipeline.csv`**.
3. When asked, confirm **the first row contains column headers**.
4. Name the board **`Deals Pipeline`**.
5. Confirm **`Deal Name`** is mapped to the **Item Name** column (it is the first column,
   so this is usually automatic).
6. Set the remaining column types:

| Column | Type |
|---|---|
| `Owner code` | Text |
| `Client Code` | Text |
| `Deal Status` | **Status** |
| `Close Date (A)` | **Date** |
| `Closure Probability` | **Status** |
| `Masked Deal value` | **Numbers** |
| `Tentative Close Date` | **Date** |
| `Deal Stage` | **Status** |
| `Product deal` | Text |
| `Sector/service` | **Dropdown** |
| `Created Date` | **Date** |

Let Monday create the Status and Dropdown labels from the data — do not type them by
hand. You should end up with 5 statuses on `Deal Status` (Won, Dead, Open, On Hold, and
a stray `Deal Status` from the repeated header rows) and 17 on `Deal Stage`. **The stray
labels are expected** — the agent drops those rows.

## Step 2 — Import the Work Orders board

Same flow with **`Work Orders.csv`**, board name **`Work Orders`**, item name column
**`Deal name masked`**.

Column types:

| Columns | Type |
|---|---|
| `Execution Status`, `Invoice Status`, `Billing Status`, `WO Status (billed)` | **Status** |
| `Nature of Work`, `Document Type`, `Sector`, `Is any Skylark software platform…` | **Dropdown** |
| `Data Delivery Date`, `Date of PO/LOI`, `Probable Start Date`, `Probable End Date`, `Last invoice date`, `Collection Date` | **Date** |
| Every `Amount…`, `Billed…`, `Collected…` column, plus `Quantity by Ops`, `Quantity billed (till date)`, `Balance in quantity` | **Numbers** |
| Everything else — `Customer Name Code`, `Serial #`, `Type of Work`, `latest invoice no.`, `AR Priority account`, `Quantities as per PO`, `Expected Billing Month`, `Actual Billing Month`, `Actual Collection Month`, `Collection status`, `Last executed month of recurring project`, `BD/KAM Personnel code` | Text |

> `Quantities as per PO` **must be Text**, not Numbers — it contains `5360 HA`,
> `2057 Acr` and bare numbers mixed together. Forcing it numeric silently destroys the
> units.

Four columns are completely empty in the source (`Expected Billing Month`,
`Actual Collection Month`, `Collection status`, `Collection Date`). Import them anyway —
the agent reports them as a known gap.

### The one thing that must not go wrong

Column **titles** are how the agent maps data. Matching tolerates case, spacing and
punctuation differences, but not renaming. If Monday truncates or alters a title during
import, fix it on the board — `/api/health` will tell you exactly which one.

## Step 3 — Get the board IDs

Open each board and read the number from the URL:

```
https://<account>.monday.com/boards/1234567890
                                    ^^^^^^^^^^
```

These are not secret.

---

## Step 4 — Get an API token

monday.com → your avatar (bottom left) → **Developers** → **My access tokens** →
copy the **API v2** token.

Read access is sufficient. The agent never writes to your boards.

**Treat this like a password.** Put it straight into `.env.local`; do not paste it into
chat, a ticket, or a commit.

## Step 6 — Verify before opening the chat

```bash
npm run dev
curl http://localhost:3000/api/health
```

A correct import looks like this:

```json
{
  "ok": true,
  "mode": "monday",
  "boards": {
    "deals":      { "rows": 342, "dropped": 5 },
    "workOrders": { "rows": 175, "dropped": 2 }
  },
  "columnMapping": { "missing": { "deals": [], "workOrders": [] } }
}
```

### Reading the result

| Symptom | Meaning | Fix |
|---|---|---|
| `rows: 342` / `175` | Correct. `dropped` counts the repeated header and blank rows the cleaner removed | — |
| `columnMapping.missing` is non-empty | A column title changed during import | Rename that column on the board to match exactly |
| `rows` far lower than expected | Import truncated, or the item limit on your plan was hit | Re-import, or check your plan's item allowance |
| Work Orders columns all unnamed | The blank first row got treated as the header | Re-import using the prepared CSV, not the original .xlsx |
| `401` / `403` | Token wrong, expired, or lacks access to the board | Re-issue the token; confirm the board is in the same account |
| `Board … was not found` | Wrong board ID | Re-copy from the board URL |

Once `ok: true` with empty `missing`, open `http://localhost:3000` and ask something.
